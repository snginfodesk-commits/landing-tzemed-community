# דף נחיתה — וובינר צמד ברזל

דף נחיתה לוובינר **״דירה בהנחה״** (יום ראשון 27/8, 20:00), מיועד לתנועה ממומנת מפייסבוק ואינסטגרם.

הריפו הזה מחובר לדומיין ולדפלוי אוטומטי — כל push ל‑`main` עולה לאוויר.

## מבנה

| קובץ | תפקיד |
|---|---|
| `index.html` | דף הנחיתה. HTML/CSS/JS בקובץ אחד, בלי תלויות חיצוניות |
| `thank-you.html` | דף התודה. פרטי הוובינר + הזמנה לקהילת הוואטסאפ |
| `assets/fonts/` | Heebo מאוחסן מקומית (woff2) |
| `assets/*.webp` | תמונות מיטביות שמוגשות בדף |
| `assets/*.jpg`, `logo-gold.png` | מקורות ברזולוציה מלאה — לא מוגשים, נשמרים לגיבוי |

`assets/msg-*.{jpg,webp}` הם צילומי ההודעות של הקרוסלה בדף הקהילה. הם **לא בשימוש** בדף הוובינר, ונשמרים כדי שאפשר יהיה לשחזר את דף הקהילה (ראו למטה).

## הגרסה הקודמת — דף הקהילה

עד 30/07/2026 הריפו הזה הגיש את **דף הנחיתה של קהילת הוואטסאפ**. הוא לא נמחק:

| ref | מה יש בו |
|---|---|
| `community-landing-v1` (tag) | הגרסה המדויקת שהייתה חיה על הדומיין |
| `backup/community-landing` (branch) | אותו דבר, כענף שאפשר לעבוד עליו |

לשחזור מלא לאוויר:

```bash
git checkout main
git revert --no-commit HEAD          # או: git checkout community-landing-v1 -- index.html thank-you.html
git commit -m "Restore community landing page"
git push
```

## זרימת הליד

`index.html` → POST ל‑webhook של n8n → הפניה ל‑`thank-you.html?name=…` → כפתור הצטרפות לוואטסאפ

השליחה עוטפת את ה‑POST ב‑`.finally()`, כך שכשל של ה‑CRM **לעולם לא חוסם** את הגולש מלהגיע לדף התודה. ליד שנכשל נשמר ב‑`localStorage` תחת `tb_leads_pending`.

הליד מתויג ב‑CRM עם `source: "קמפיין ממומן"` ו‑`lecture: "וובינר דירה בהנחה"` — התיוג הזה הוא מה שמפריד בין לידי הוובינר ללידי הקהילה בגיליון.

## תאריך הוובינר

התאריך מופיע **בארבעה מקומות** ב‑`index.html` וב‑`thank-you.html` (ה‑kicker בהירו, ה‑meta‑strip, השורה `.when` בטופס, והמשפט בדף התודה). דחייה של הוובינר מחייבת עדכון של כולם.

## החלטות טכניות שכדאי להכיר לפני עריכה

רוב התנועה מגיעה מ‑**webview של אינסטגרם/פייסבוק**, שמתנהג אחרת מדפדפן רגיל:

- **בלי `IntersectionObserver`** — ה‑callbacks שלו לא נורים באופן אמין ב‑webview. סרגל ה‑CTA הדביק משתמש ב‑`scroll` listener רגיל.
- **בלי `requestAnimationFrame`** לאלמנטים קריטיים — הוא עלול להיחנק.
- **בלי AVIF** — התמיכה ב‑webview לא אחידה. WebP נתמך בכל מקום רלוונטי.

### פונטים

Heebo הוא **פונט משתנה (variable font)** — קובץ אחד לכל תת‑קבוצה מכסה את כל המשקלים 100–900. לכן יש רק שני קבצים (`hebrew`, `latin`) ולא אחד לכל משקל.

הפונטים מאוחסנים מקומית בכוונה: ה‑stylesheet של Google Fonts היה המשאב היחיד בדף שחסם רינדור, והוא עלה שתי התקשרויות DNS+TLS לצד שלישי.

### צבעים

ירוק (`--wa`) הוא צבע הפעולה היחיד לאורך כל המשפך: ה‑CTA בהירו, כפתור השליחה בטופס, וכפתור הוואטסאפ בדף התודה. זהב (`--gold`) הוא צבע המותג בלבד — כותרות, מסגרות, מפרידים — ולעולם לא פעולה.

## עריכה

הכל סטטי. פותחים את `index.html` בדפדפן — אין שלב build, אין תלויות, אין `npm install`.

לתצוגה מקומית עם נתיבים תקינים:

```bash
python3 -m http.server 8931
# http://localhost:8931
```

## העלאה לאוויר

הדף סטטי לחלוטין. בכל שירות אירוח, מומלץ לוודא:

- **Brotli או Gzip** — מקטין את ה‑HTML מ‑28KB ל‑כ‑8KB
- **`Cache-Control` ארוך על `assets/`** — התמונות והפונטים לא משתנים
